Проверено 24 октября 2026 года в личном кабинете и ispmanager.

## Выполнение

- Созданы каталоги `/www` и `/www/chinatown.site` с правами 755.
- Выпущен и включён бесплатный сертификат Let's Encrypt `chinatown.site_le1` для `chinatown.site` и `www.chinatown.site`, действителен до 21 января 2027 года. Панель подтвердила успешное получение.
- Проверка `curl` с обычной проверкой TLS прошла: `https://chinatown.site/` отвечает HTTP 403 до загрузки файлов в пустой каталог.
- Все 48 локальных тестов прошли, сборка и ZIP-архив повторно подготовлены.
- Загрузка файлов, перенаправление HTTP на HTTPS и подключение Formspree ещё выполняются. Во вкладке Formspree запрошен вход пользователя.

## Что уже есть

- Активный хостинг «Хост-Лайт»: 7 ГБ для файлов, оплачен до 16 октября 2027 года.
- Домен `chinatown.site`, псевдоним `www.chinatown.site`. Домен зарегистрирован до 3 ноября 2026 года.
- DNS-серверы домена: `ns1.hosting.reg.ru`, `ns2.hosting.reg.ru` — серверы виртуального хостинга Рег.ру.
- Панель ispmanager, сервер `server131.hosting.reg.ru`, IPv4 `37.140.192.146`.
- В настройках сайта индексная страница — `index.html`, корневая директория — `/www/chinatown.site`.
- Сайт статический: серверный Node.js и база данных для этой сборки не нужны. Node.js используется локально для проверок и сборки.

## Что мешает публикации сейчас

1. **Отсутствует каталог сайта.** В корне файлового менеджера есть только `logs`. Команда «Файлы сайта» возвращает ошибку получения информации о `/var/www/u3686152/data/www`. Нужно создать каталоги `www`, затем `chinatown.site` внутри него. В панели итоговый путь — `/www/chinatown.site`, полный серверный путь — `/var/www/u3686152/data/www/chinatown.site/`.
2. **Сертификат самоподписанный.** В разделе «SSL-сертификаты» единственный сертификат `chinatown.site` имеет тип «Самоподписанный». Для обычного доступа по HTTPS его нужно заменить доверенным, например бесплатным Let’s Encrypt.
3. **Подписка не подключена.** В `index.html` у `#subscribe-form` стоит `https://formspree.io/f/YOUR_FORM_ID`. Для приёма заявок нужно указать ID своей формы Formspree и после этого пересобрать сайт. Без этого интерфейс сайта опубликуется, но заявки отправляться не будут.

## Порядок публикации

1. В проекте выполнить:

   ```sh
   npm test
   npm run build
   ```

   Результат находится в `dist/`. Проверка 24 октября: все 48 тестов прошли, сборка завершилась успешно.

2. Упаковать **содержимое** `dist/` в ZIP. В корне архива должны находиться `index.html`, другие страницы, стили, `src/`, `assets/` и `docs/`. Дополнительной папки `dist` внутри архива быть не должно. Репозиторий целиком, `.git`, локальные настройки и `video-originals` загружать не требуется.

3. В личном кабинете Рег.ру открыть услугу «Хост-Лайт» → «Войти в панель». В ispmanager открыть «Менеджер файлов» и создать отсутствующие папки из пункта выше. Каталог `logs` относится к журналам и не является папкой сайта.

4. Открыть `/www/chinatown.site` → «Загрузить», выбрать ZIP. После загрузки выделить архив → «Архив» → «Извлечь». Проверить, что `index.html` находится непосредственно в `/www/chinatown.site`, рядом с `src` и `assets`.

5. Проверить доступность сайта по HTTP. Если домен не ведёт на этот хостинг, проверить его DNS-записи: они должны соответствовать IP-адресам сайта в ispmanager. NS-серверы уже указаны правильно; публичные A/AAAA-записи в рамках этой проверки отдельно не проверялись.

6. В «SSL-сертификаты» выбрать «Добавить сертификат» → Let’s Encrypt и выпустить сертификат для `chinatown.site` и `www.chinatown.site`. Для выпуска домен должен быть доступен и указывать на хостинг. В «Сайты» → настройки `chinatown.site` выбрать новый сертификат; после проверки HTTPS включить перенаправление HTTP → HTTPS. Сохранить настройки.

7. Открыть `https://chinatown.site`, `/about.html` и `/article.html`. Проверить загрузку шрифтов, изображений и видео, открытие окна подписки и, после подключения Formspree, тестовую отправку формы.

Обновления публикуются тем же способом: проверки → новая сборка → загрузка и распаковка. Перед заменой существующей версии сохранить её резервную копию. Нынешний GitHub Actions workflow публикует сайт только в GitHub Pages; обновления в GitHub сами по себе на Рег.ру не попадут.
