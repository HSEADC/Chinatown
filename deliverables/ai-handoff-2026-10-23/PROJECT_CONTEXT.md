## 1. Самое важное перед началом

1. **Сейчас открыт баг прокрутки во встроенном окне на телефоне.** После коммита `d664ac0` пользователь снова сообщил: «скрол на мобилке так и не работает», затем уточнил: **только во встроенном окне приложения**. Успех тестов не закрывает эту проблему. Перед продолжением сверить последние изменения и результат того чата.
2. **Сайт — статический прототип медиа с одной действующей статьёй.** Нет CMS, базы данных, собственного API, авторизации и настоящего каталога публикаций.
3. **Не менять зафиксированную CTA при работе над страницами.** Розовая прямоугольная кнопка, белые текст и стрелка, общий `action-button`. Все её размеры и состояния принадлежат компоненту и общим токенам.
4. **Только две типографические ступени:** телефон ≤760 px и десктоп ≥761 px. Никакой подгонки шрифта по ширине. Граница правой панели 1200 px — изменение компоновки, а не новая шрифтовая ступень.
5. **Текст статьи редактируется в `src/article-copy.js`; композиция — в `src/article-view.js`; справки — в `src/article-context-data.js`.** Сгенерированный текст `article.html` отдельно не править.
6. **Песенные сцены:** минимум четыре исходные строки или один полный короткий припев; сразу после — разбор именно показанного фрагмента. Куплет сейчас содержит пять строк, припев — четыре. Не дописывать и не повторять строки для количества.

## 2. Что это за продукт

**CHINATOWN — медиа о нефорах, независимой культуре, музыке, людях и местах сцены.** В интерфейсе встречаются CHINATOWN.RU, CHINATOWN.SITE и доменный текст `chinatown.ru`; рабочая публикация находится на GitHub Pages. Единого переноса бренда на один домен в коде пока не сделано. Не менять адреса массовой заменой без задачи.

Текущая работа сосредоточена на читательском опыте: выразительная обложка, спокойный основной текст, крупные песенные сцены, связанные справки, изображения и городские видео. Правая панель даёт дополнительную информацию и развлекательный ритм во время чтения. Она должна помогать понять материал и позволять отвлечься на связанный объект, сохраняя место в статье.

Последняя сформулированная пользователем задача мобильного формата: сохранить это разнообразие на телефоне, где читают чаще; дополнительный контент должен быть заметным, доступным для повторного открытия и показывать смену материала, при этом чтение статьи должно оставаться центральным действием. Реализован нижний формат шторки. Полное раскрытие выполняется по действию читателя; автоматическое первое появление — компактное превью.

Редакционный голос: разговорный музыкальный журнал, допускается лёгкая дерзость, без искусственного молодёжного сленга, академического тона, повторов и натянутых интерпретаций. Персонаж песни и биография музыканта — разные вещи. Обязательные объяснения остаются в основном тексте; справки дают дополнительную глубину.

Будущие карта, архив, теги, подборки, плейлисты, персонализация и монетизация обсуждались в исследованиях. Это не описание работающего сайта и не утверждённое поручение строить все эти функции.

## 4. Как запустить

Стек: HTML, CSS и нативные JavaScript ES modules. Сборщик, React/Vue, TypeScript и сторонние runtime npm-зависимости отсутствуют. В `package.json` нет `dependencies`/`devDependencies`, lock-файла нет. Для обычной работы установка npm-пакетов не требуется.

```sh
git clone https://github.com/pentaoo/media.git
cd media
npm run dev
```

Открыть `http://localhost:4173/`. Локально проверено с Node **v22.23.2**, npm **12.0.2**. CI использует Node **24**. Для воспроизводимой среды удобно использовать версию CI.

| Команда | Действие |
| --- | --- |
| `npm run dev` | `node scripts/serve.mjs`, отдаёт корень репозитория |
| `PORT=4182 npm run dev` | тот же сервер на другом порту |
| `npm test` | встроенный Node test runner, сейчас 48 тестов |
| `npm run article:generate` | обновляет `article.html` и содержимое/заголовок `about.html` из JS-шаблонов |
| `npm run build` | сначала генерация HTML, затем пересоздание `dist/` и копирование публикационного набора |
| `npm run video:prepare` | перекодирование по монтажным рецептам; нужны исходники, ffmpeg и ffprobe |

Локальные порты 4173, 4182, 4186 встречаются в истории превью. Это не разные версии продукта. Проверять, какой сервер и какой checkout открыт в браузере.

Для обычного запуска, тестов и сборки **не нужны ffmpeg и исходные концертные записи**: подготовленные медиа уже лежат в Git. Тесты MP4 читают готовые файлы средствами Node. Нельзя запустить полный набор тестов из текстового архива передачи без восстановления `assets/` из репозитория.

Сервер поддерживает byte ranges для видео (`206`, `416`, start/open-ended/suffix), HEAD и проверку выхода за корневую директорию. Это служебный файловый сервер, а не backend продукта. Ссылки рассчитаны и на публикацию в подпапке `/media/`; сохранять относительные URL и `new URL(..., import.meta.url)`.

## 8. Зафиксированные правила дизайна

### CTA и поле

- Первый акцент: `#fc5cff`, прямоугольник без скруглений, белые текст и стрелка. Компонент `action-button` реализован по Figma `276:101`; мобильные варианты — `388:748` и `388:752`.
- Вайт-лист и подписка используют одну реализацию. JS API: `mountActionButton`, `mountActionButtons`, `createActionButton({ label, type, variant })`. В статическом HTML — нативный `button`/`a` с `.action-button` и `data-action-button`.
- Группа текста и стрелки центрируется целиком. Страница задаёт положение и доступную ширину; цвет, высота, типографика, внутренние отступы и иконка принадлежат общему компоненту/токенам. Не вводить переопределения на странице.
- Hover стрелки: +4 px за 180 мс; active: +2 px; текст и габариты неподвижны. На touch, при reduced motion и у disabled движения нет. Общие стили `a:hover`/`a:focus-visible` исключают CTA; текст и стрелка остаются белыми.
- Десктоп: кнопка и иконка 64 px, текст 24/32. Телефон: 32 px, иконка 32 px, текст 12/16; невидимая область касания расширена до 44 px.
- Поле: десктоп 64 px, телефон 34 px с рамкой 1 px. Мобильный плейсхолдер 30%. Размеры — в токенах, общее оформление — `email-field.css`.
- Дизайн CTA менять только по прямой просьбе пользователя. После затрагивания формы/компоновки проверять обе CTA, центрирование, отсутствие переполнения, открытие диалога и отправку.

Гарнитуры: Benzin для display/акцентных ролей, Giga Sans для прозы; глитч использует Elion Italic, East Gates и Sigma Boy поверх исходного набора. Локальные файлы в `assets/fonts/`, синтез начертаний отключён. Рукописный акцент в редакционном тексте удалён; Elion нужен глитчу.

Запрещена подгонка размера текста/основных контролов через `clamp()`, `vw`, `cqw` и промежуточные профили. Геометрия колонок, высота сцены и отступы могут быть гибкими. Контейнерная ширина не превращает десктопную карточку в мобильную. Для переполнения менять переносы и компоновку.

Структурные границы:

- ≤760 px: мобильная типографика, мобильная оболочка статьи и нижняя шторка.
- 761–1199 px: десктопная типографика, верхний хедер; справки в потоке/отдельном экране.
- ≥1200 px: десктопная типографика и правое редакционное окно.
- Заголовки разделов дополнительно ориентируются на ширину области статьи 860 px; это поведение sticky-анимации, не отдельная адаптивная шкала. В коде остаётся нарушение фиксированных размеров — см. раздел 16.

На широком экране основа — пять колонок с полями и промежутками 32 px. Статья использует первые четыре, правое окно — пятую и внешнее правое поле. Поле телефона — 20 px, обычный промежуток — 12 px. Не использовать этот абзац вместо чтения действующего CSS конкретной страницы.

## 9. Справки, правая шторка и приоритеты

Ключевой принцип: **у материала один настоящий DOM-узел**. Он перемещается между статьёй, правой панелью, мобильным отдельным экраном и нижней шторкой. Нельзя делать независимые копии с расходящимися данными и просмотрщиками.

Чистая логика `selectContextState` задаёт приоритет:

```text
ручной выбор → временный preview → взаимодействие с текущим материалом
             → автоматическая глава → фоновое видео
```

Ручной выбор переживает автоматические переходы и действует до закрытия. Взаимодействие/фокус/выделение удерживает автоматическую карточку; после завершения она догоняет актуальную главу. Зона устойчивости на границе глав — 24 px. `anchorId` задаёт конкретный связанный абзац; не выбирать источник по похожим словам.

Видимое пояснение связано с подсветкой исходного текста по строкам, без изменения его размеров. Подсветка доступна и для правого окна; пропадает при сворачивании. Историческая фраза в `docs/article-context.md`, что это только проектная функция, уже устарела после мобильной реализации.

Десктопная оболочка ≥1200 px:

- Свёрнута в полосу 40 px; hover/focus даёт превью 72 px. Превью не двигает текст и не активирует карточку.
- Нажатие/Enter/Space раскрывает панель, переход около 280 мс. Закрывает постоянная стрелка. Сворачивание сохраняет материал; Escape снимает ручной выбор.
- Предпочтение хранится в `sessionStorage`, ключ `chinatown:scene-rail:collapsed`; обложка и концертная сцена временно скрывают всю панель вместе с краем.
- Смена карточек идёт горизонтально за 360 мс; более поздний источник входит справа, более ранний — слева. Направление определяется порядком исходных источников в статье. Ручного горизонтального листания нет.
- `context-pager.js` управляет настоящими узлами; уходящая страница получает `inert`/`aria-hidden`. Быстрые переключения продолжаются из текущего положения.
- Длинный заголовок через секунду начинает бегущую строку 32 px/с с промежутком 32 px. Hover/focus, скрытие и просмотрщик ставят её на паузу. Reduced motion показывает полный переносимый заголовок; доступное имя одно.
- Видеоэлемент и состояние сохраняются между внутренними маршрутами. При исходно узком экране боковые видео не запрашиваются; загруженное ранее видео при сужении остаётся на паузе.

Упоминания артиста, трека и альбома открывают справочную карточку. На широком экране hover/focus показывает preview через 180 мс, уход возвращает контекст через 280 мс; клик закрепляет. После ручного сворачивания hover не раскрывает панель, клик раскрывает. Сноски и ссылки доступны с клавиатуры, без JS работают якорями.

На 761–1199 px короткая заметка остаётся в потоке, большие справки открываются отдельным экраном с возвратом к статье. Back закрывает, Forward восстанавливает; фокус и позиция чтения сохраняются.

Просмотрщик `article-images.js`: увеличенное цветное изображение на затемнённом чёрно-белом фоне, лёгкий наклон по указателю, закрытие кнопкой/фоном/Escape/Back, поддержка Forward. Пока он открыт, размещение контекста заморожено, чтобы resize не переместил исходную карточку. Reduced motion отключает трансформации.

## 10. Мобильная оболочка — актуальная механика

Три FAB по Figma `404:664`: меню и поиск 32×32 с иконкой 24; дополнительный материал 56×56 с иконкой 32. Промежутки 24 px, правый/нижний край 12 px плюс safe area. Hit area маленьких кнопок расширена до 44 px без пересечения.

`mobile-shell-state.js` хранит `mode`, `snap`, `id`, `unread`, `introduced`, `dismissed`. Положения только **`hidden`, `preview`, `expanded`**. Промежуточное состояние 40% удалено по прямой просьбе пользователя.

- Превью: 88 px, на низком окне максимум 25% доступной высоты. Полное раскрытие: высота окна минус 48 px статьи сверху.
- Первое настоящее пояснение автоматически вводит компактное превью. Фоновое видео само по себе не вызывает первого открытия.
- FAB и явная ссылка открывают актуальную справку полностью. Ручка и заголовок переключают превью/полное раскрытие. Стрелка сворачивает в превью, затем скрывает.
- Drag работает за шапку/ручку. В превью край содержимого принимает вертикальный свайп для статьи, а нажатие раскрывает. В полной карточке содержимое скроллится отдельно.
- Полное скрытие сохраняется на сессию статьи. Новая справка не раскрывает панель снова: FAB получает точку и один короткий поворот при новом непрочитанном состоянии.
- Поиск и меню временно занимают отдельную нижнюю поверхность, запоминают положение справки и возвращают его при закрытии. Только эти overlay-режимы блокируют основную статью через `overflow` и `inert`.
- Escape, Back и кнопки закрытия должны освобождать блокировку и восстанавливать фокус. Системная клавиатура учитывается через `visualViewport`, safe area — у нижнего края.
- Состояния introduced/dismissed: `sessionStorage` с ключом `chinatown:mobile-shell:madk1d-tak-pohuy` для текущей статьи.

Формат «Китай-город» использует только `kitay-*` из видеоманифеста, загружается при необходимости, начинает без звука. Есть отдельное включение звука, пауза, следующий ролик и возврат к справке. Выход выключает звук; reduced motion / экономия трафика отключают автозапуск; скрытая вкладка приостанавливает воспроизведение.

**Ограничение доказательств:** описанное выше — реализованный контракт и результаты прежних Chromium-проверок. Последняя жалоба пользователя показывает, что фактическая прокрутка во встроенном окне на его телефоне всё ещё ломается. Настоящая экранная клавиатура iOS/Android также остаётся отдельной проверкой.

## 12. Песенные сцены

Обе сцены используют один формат `quoteSceneView`, `data-quote-scene` и `data-quote-line`, одну анимационную механику и локальный фрагмент `madk1d-chorus`.

- Контроллер работает и на телефоне, и на десктопе. Сцена закрепляется; строки проходят позицию чтения и выделяются по очереди. Текущая белая, следующая около opacity 0,4, прошедшая — около 0,18.
- Короткие мягкие остановки каждой **исходной строки**, замедление/ускорение и сглаживание. Быстрый жест снимает удержание и сглаживание на свою инерцию. Скролл остаётся нативным и работает в обе стороны.
- Фон появляется при подходе к позиции чтения, полностью виден в основной фазе и гаснет после последней строки, раскрывая следующий разбор. Правая панель скрывается **сразу с началом сцены**, без промежуточного переключения на городское видео; выбранная справка сохраняется.
- Это обычное muted HTML video, без YouTube iframe/API и без музыкального плеера. Загружается при приближении, зацикливается, ставится на паузу вне сцены/в скрытой вкладке. Фото из Figma — fallback при ошибке/запрете автозапуска.
- Reduced motion и отсутствие JavaScript дают статичную читаемую сцену.
- Разделители `***` в куплете обозначают пропуск, не считаются строками и не получают остановок. Три ссылки Genius находятся в подписи. Концерт на фоне не выдаётся за синхронное исполнение процитированного куплета.

Обязательное редакционное правило повторено в `AGENTS.md`: ≥4 строки, кроме целого припева короче четырёх; короткий припев ровно один раз; сразу следующий основной текст разбирает показанное. Если другого фрагмента не хватает, обратиться к редактору за фрагментом, а не сочинять дополнение. Переносы и отдельные DOM-элементы количество строк не увеличивают.

## 14. Главная, подписка, эффекты и DEV

Запусковая главная: текст «Скоро на CHINATOWN.SITE — медиа о нефорах», ссылка «О нас», Telegram, визуальный пункт TikTok без рабочего адреса, общая CTA вайт-листа. Глитч заменяет гарнитуру отдельных букв, сохраняя символы и базовую вёрстку. На мыши эффект обновляется около каждых 200 мс, возврат после ухода около 3 сек; на телефоне работает от скролла. Изменение ширины и переносы требуют повторных измерений слоя. Ветки compact/редких фоновых замен сейчас недостижимы — не путать с действующим hover/scroll-глитчем.

Окно подписки открывается CTA и через **45 секунд активного просмотра главной**, один раз за сессию вкладки. В статье этого автоматического приглашения нет. Крестик/фон/Escape закрывают, фокус возвращается, фон получает `inert`, есть обход фокуса и состояния валидации/сети/429.

**Настоящая отправка не настроена:** в `index.html` action `https://formspree.io/f/YOUR_FORM_ID`. Контроллер проверяет адрес, показывает «Форма пока не настроена» и не выполняет POST. Для включения нужен настоящий endpoint Formspree. Принятие заявки сервисом само по себе не означает включение человека в email-рассылку: дальнейший workflow не реализован. Собственного backend/почтового сервиса/Telegram-бота в этом checkout нет.

DEV доступен на localhost или по `?dev=1`, `?dev=0` отключает его. Код панели загружается условно. Рабочая вкладка сетки показывает направляющие и меняет реальные поля/промежутки, профили раздельные: landing/article × desktop/mobile. На телефоне статья одноколоночная.

## 20. Как передать пакет и начать следующий сеанс

В `START_HERE.md` есть готовый промпт. Достаточно передать этот документ, `WORK_IN_PROGRESS.md` и дать доступ к репозиторию. Если новый ИИ принимает архивы, приложить `../ai-handoff-2026-10-23.zip`: в нём этот контекст, стартовый промпт, manifest с SHA-256, **текстовый снимок базы** с локальным аудитом и отдельно **свежая незавершённая работа**.

В архив намеренно не входят бинарные фото, шрифты, видео, вся Git-история, `dist`, `node_modules`, внешние recordings и `video-originals`. Это пакет контекста и исходного текста, **не автономная копия работающего сайта**. Для запуска клонировать репозиторий с `assets/` и проверить коммит; для повторного монтажа отдельно перенести настоящие исходные видео. Обычный `git clone` не содержит неотслеживаемый аудит и новые материалы этой передачи до их коммита — они сохранены в архиве.

Рекомендуемый первый проход следующего ИИ:

1. Прочитать этот файл, `WORK_IN_PROGRESS.md` и `AGENTS.md`, сверить Git/свежие изменения, получить конкретную новую задачу.
2. Проверить, завершилась ли диагностика мобильного скролла в другом чате. До этого не объявлять его исправленным и не накладывать параллельный конфликтующий патч.
3. Изучить только модули задачи и реальные Figma-узлы при необходимости; отделить текущую реализацию от архивных предложений.
4. Выполнить задачу в существующей системе, сохранить общие компоненты, редакционные данные, fallback и teardown.
5. Запустить подходящие проверки, затем сообщить конкретные изменения, результат и оставшиеся ограничения. Коммит/push/публикацию выполнять в рамках новой явно поставленной задачи.

Документ фиксирует передачу, а не замораживает проект. Если код или более позднее решение пользователя расходятся с этим срезом, обновить контекст и работать по актуальным данным.
